# ADR 0004 – Explicit "Undo delete" instead of SwiftData's undo manager

- Status: accepted
- Date: 2026-10-08

## Context

Attaching an `UndoManager` to the `ModelContext` and undoing a deletion after `save()` crashes with
`SwiftData/DataUtilities.swift: Fatal error: A snapshot should exist before creating a new snapshot
for undo` (reproduced in a unit test on Xcode 27 / macOS 27). Services save immediately, so this path
is hit on every delete.

## Decision

- No undo manager on the model context.
- `TaskService.deleteUndoably(_:)` captures a value snapshot (`DeletedTasks`: record, children,
  attachments, activity, dependents) and `restore(_:)` re-creates the tasks with their identifiers.
- The app registers this restore with the window's `UndoManager` (Edit ▸ Undo, ⌘Z, shake to undo)
  and offers an "Undo" button in a toast.

## Consequences

Undo is limited to deletions, the most destructive action. Restores are covered by `UndoTests`.
